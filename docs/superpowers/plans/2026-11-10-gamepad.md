# LLM Chat on the gamepad — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every LLM Chat command (move, confirm, back, and the F-key commands) comes from `picocalc.gamepad`, so a Bluetooth controller and keys rebound in Settings > Controls drive the app, while typing stays on the keyboard and a key that types never also acts as a pad button.

**Architecture:** A new `src/pad.lua` is the one place that reads `picocalc.gamepad`. `App:step` reads the frame's key events first (as today, into `s:key(ev)`), then hands the pad to the screen once (`s:pad(pad)`) unless a key event changed the screen or called `app:settle()`. Screens without a focused text field (Recent chats/Programs, Settings rows, the error screen) read only `pad:nav()` and ignore key events; a screen with a focused field (the chat's compose box, the picker's filter, a Settings key or the instructions) keeps reading the keyboard for typing and passes its typing set to the pad, which drops a button press when one of that button's keys is a typing key that is down or was pressed this frame. Hints name keys with `pad:label()` (getLabel).

**Tech Stack:** Lua 5.4 on the PicoDeck `picocalc.*` API; host tests `lua tests/run.lua` (own runner, `tests/t.lua` asserts, `tests/fakepc.lua` fake picocalc) and `build/lua32` (32-bit numbers); E2E pytest against PicoDeck's SDL simulator (`tests/e2e/`, `make e2e`) with a loopback fake API.

**Spec:** No separate spec file. The design is the user's scope rulings of 2026-11-10 (copied into Global Constraints) plus the firmware API in `/home/keith/Projects/PicoDeck/picodeck/.worktrees/gamepad-apps/docs/API-Gamepad.md` (merged into PicoDeck `develop` at a86e525a). ## Decisions this plan makes

**Focus rule.** While a text field has focus, the keys it uses are read only as keys: a pad press is dropped when one of its button's bound keys is in the field's typing set and is down or was pressed this frame. Everywhere else every command comes from `getNavPressed()` and key events are ignored. F1–F5 and Tab are never read as keys anywhere; they act only as the pad buttons they are bound to (by default Start, L, R, A, B, Select).

- Typing sets (getLabel key names): `Pad.TEXT` (compose box, Settings key field and instructions) = A–Z, Space, Left, Right, Up, Down, Enter, Esc, Bksp, Del, Ctrl. `Pad.FILTER` (picker filter) = the same less Up, Down, Enter, Esc (the picker reads those from the pad).
- The chat reads `getButtonsPressed()`/`getButtonsRepeated()` (no Enter→A / Esc→B folding, since Enter sends and Esc stops/quits there); list screens and the picker read `getNavPressed()`.
- "Pressed this frame" matters: the probe in the simulator showed a typed letter's down/char/up events and its pad edge arrive in the same frame with `isKeyDown` already false, so the App records every key event's code (`pad:saw(ev)`) and the guard checks those as well as `isKeyDown`.

**Controller-only player.** From the chat: Start → Recent chats/Programs, A → model picker, B → Settings, L → new chat, R → run the newest program, D-pad Up/Down → scroll the conversation. Every list screen: D-pad, A confirm, B back. Typing a message (and so sending one) needs a keyboard; a controller can read and browse chats, pick models, change Settings (B leaves a key edit it cannot type into), run programs and ask for a fix. Stopping a reply needs Esc. Quitting is the system menu (Home) → Exit App, as for every PicoDeck app.

**F-key collisions (default bindings).**

| Key | Pad | Today | After (keyboard) | Pad button does |
|---|---|---|---|---|
| F1 | Start | Chat: Recent chats | Chat: Recent chats; **Picker: Settings** (new) | same as the key |
| F2 | L | Chat: new chat; Chats tab: new chat; Picker: refresh lists | unchanged | same |
| F3 | R | Chat: run program; Error screen: run again | unchanged | same |
| F4 | A | Chat: model picker; **Programs tab: open its chat** | Chat: model picker; on every list screen = Enter (**Programs tab: run**) | Chat: picker; lists: confirm |
| F5 | B | Chat: Settings; **Picker: Settings** | Chat: Settings; on every list screen = Esc (**Picker: clear filter / back**); Settings edit: end it | Chat: Settings; lists: back |
| Tab | Select | nothing | nothing | nothing |
| Bksp | Y | edit; lists: nothing | edit; **Programs tab: open its chat** (moved from F4) | Programs tab: its chat |
| Del | X | edit; lists: delete | unchanged | lists: delete |
| arrows / Enter / Esc | D-pad / (A) / (B) | as keys everywhere | keys while typing; through the pad on list screens | lists: move / confirm / back; chat: D-pad scrolls |

**Keyboard behaviour changes** (default bindings): Programs tab F4 runs (its chat moved to Backspace); picker F5 backs out (Settings moved to F1, and the no-key row says "(F1)"); F4/F5 now also confirm/back on every list screen and F5 ends a Settings edit; a Settings dropdown no longer filters by typing; on list screens the arrows, Enter, Esc, Del, Backspace and F-keys follow Settings > Controls; picker Shift+Up/Down now pages on the device (PgUp/PgDn); a key typed in the same frame after an F-key acts before it (a frame is ~10 ms).

**Left as they are, on purpose:** the stored chat notes "This chat is getting long; F2 starts a new one." (matched by its text when a chat is reopened) and "Add your … key in Settings (F5), or pick another model (F4)." are chat history, not hints, and are true with the default bindings (follow-up line in Task 7). Direction hints stay literal ("Up/Down"). Keyboard-only keys in hints stay literal ("Enter send", "Esc stop", "Enter save   Esc cancel").

## Global Constraints

- Firmware API (`API-Gamepad.md`): `getNavPressed()` = the D-pad with auto-repeat, the other buttons' press edges (no repeat), `PAD_A` for an Enter press and `PAD_B` for an Esc press unless that key is bound to a button (then that button only); the same value for every call in one frame. `getButtonsRepeated()` = presses plus repeat edges. `getButtonsPressed()` = press edges only. `getLabel(btn [, slot])` = key name or `nil` (raises for anything but one `PAD_*` bit or slot 0/1). Key names: `Up Down Left Right Enter Esc Tab Bksp Del Space F1`–`F5 A`–`Z Ctrl`.
- Bits (PicoDeck `src/os/os.h`): `PAD_UP` 1, `DOWN` 2, `LEFT` 4, `RIGHT` 8, `A` 16, `B` 32, `X` 64, `Y` 128, `L` 256, `R` 512, `START` 1024, `SELECT` 2048. `BTN_SHIFT` is `1 << 19`.
- Default bindings: arrows = D-pad, A = F4, B = F5, X = Delete, Y = Backspace, L = F2, R = F3, Start = F1, Select = Tab. A bound key still reports as itself through `pollEvent`; a controller press makes no key event.
- Key codes (API-Input "Key codes"): Up `0xB5`, Down `0xB6`, Left `0xB4`, Right `0xB7`, Enter `0x0A`, Esc `0xB1`, Backspace `0x08`, Del `0xD4`, Space `0x20`, Ctrl `0xA5`; with Shift: PgUp `0xD6`, PgDn `0xD7`, Insert (Shift+Enter) `0xD1`, End (Shift+Del) `0xD5`. PgUp/PgDn/Insert/End have no `BTN_*` bit.
- `app.json` `min_firmware` becomes `"0.7.0"`. `version` stays `"2.0.0"`; no tag.
- No raw-key fallback for older firmware: `main.lua` refuses to start without `picocalc.gamepad.getNavPressed` (splash "LLM Chat needs a newer PicoDeck" / "Update the firmware to 0.7.0 or later").
- Hints name pad buttons with `pad:label()`; a button with no usable key there is left out of the hint (a program card's cap shows `-`).
- No test needs the network: host tests use `tests/fakepc.lua`'s responder; E2E uses `tests/e2e/fake_api.py` on 127.0.0.1.
- Style: Lua, 4-space indents, comments that say why; tests are named functions in the table a `tests/test_*.lua` file returns; commit subjects in the repo's style (`feat(pad): ...`, `test(e2e): ...`, `docs: ...`).

## Review Focus

1. **Text typed in the same frame as a pad command** (a fast typist, or a long frame while a reply streams): the text must land in the compose box and the draft before Start leaves the chat. Pinned by Task 5's `typed_text_survives_a_pad_command`.
2. **Enter bound to a pad button in Settings > Controls** (e.g. A = Enter, F4): in the compose box Enter must still send and A must not also open the picker. Pinned by Task 5's `enter_bound_to_a_still_sends`.
3. **A controller's D-pad held in a list:** repeat edges must keep moving the selection (nav, not press edges). Pinned by Task 2's `held_dpad_repeats`.
4. **Shift+Down on the device** is PgDn (`0xD7`), a key with no `BTN_*` bit that the gamepad reads as Down: the picker must page, and the event must not reach the filter. Pinned by Task 4's `pgdn_pages`.
5. **Controller B with a Settings dropdown open:** it must close the dropdown, not leave Settings or change the value. Pinned by Task 3's `b_closes_an_open_select_first`.

    -- alternate} key names, the firmware's defaults; a test rebinds by
    -- assigning. Each input.update reads the keys queued since the last one
    -- (F.key, F.type): each presses the button it is bound to; Enter and Esc
    -- bound to none add A and B to getNavPressed only. F.pad(name, ...)
    -- presses a controller's buttons (no key event) and F.padRepeat(name, ...)
    -- adds repeat edges, both for the next update. For that frame
    -- input.getButtons() holds the queued keys' buttons and modifiers, and
    -- input.isKeyDown(code) is true for their codes and for F.held[code].
    F.binds = { [1] = { "Up" }, [2] = { "Down" }, [4] = { "Left" }, [8] = { "Right" }, [16] = { "F4" },
                [32] = { "F5" }, [64] = { "Del" }, [128] = { "Bksp" }, [256] = { "F2" }, [512] = { "F3" },
                [1024] = { "F1" }, [2048] = { "Tab" } }
    F.padNext, F.repNext, F.held = 0, 0, {}
    F.padFrame = { pressed = 0, repeated = 0, nav = 0, held = 0, down = {} }
    local function buttonOf(name)
        for b, keys in pairs(F.binds) do
            if keys[1] == name or keys[2] == name then return b end
        end
    end
    function input.update()
        local fr = { pressed = F.padNext, nav = 0, held = 0, down = {} }
        for _, ev in ipairs(F.events) do
            if not ev.padSeen then
                ev.padSeen = true
                local b = ev.padKey and buttonOf(ev.padKey)
                if b then fr.pressed = fr.pressed | b
                elseif ev.padKey == "Enter" then fr.nav = fr.nav | PAD.A
                elseif ev.padKey == "Esc" then fr.nav = fr.nav | PAD.B end
                if ev.key then fr.down[ev.key] = true end
                if ev.type == "down" then fr.held = fr.held | (ev.button or 0) | (ev.mods or 0) end
            end
        end
        fr.repeated = fr.pressed | F.repNext
        fr.nav = fr.nav | fr.pressed | (F.repNext & (PAD.UP | PAD.DOWN | PAD.LEFT | PAD.RIGHT))
        F.padNext, F.repNext, F.padFrame = 0, 0, fr
        F.service()
    end
    function input.getButtons() return F.padFrame.held end
    function input.isKeyDown(k) return F.padFrame.down[k] or F.held[k] or false end
    local gamepad = {}
    for name, v in pairs(PAD) do gamepad["PAD_" .. name] = v end
    function gamepad.getButtons() return 0 end
    function gamepad.getButtonsPressed() return F.padFrame.pressed end
    function gamepad.getButtonsReleased() return 0 end
    function gamepad.getButtonsRepeated() return F.padFrame.repeated end
    function gamepad.getNavPressed() return F.padFrame.nav end
    -- As the firmware: an error for anything but one PAD_* bit or slot 0/1.
    function gamepad.getLabel(btn, slot)
        slot = slot or 0
        local keys = F.binds[btn]
        if not keys or (slot ~= 0 and slot ~= 1) then error("bad argument to 'getLabel'") end
        return keys[slot + 1]
    end
    local function padBits(names)
        local m = 0
        for _, n in ipairs(names) do m = m | assert(PAD[n:upper()], n) end
        return m
    end
    function F.pad(...) F.padNext = F.padNext | padBits({ ... }) end
    function F.padRepeat(...) F.repNext = F.repNext | padBits({ ... }) end

local Pad = require("src.pad")

-- A Pad on a fake picocalc; frame() runs one input frame as App:step does.

Header comment: the module is what every screen's commands come from; a screen with a focused text field passes its typing set, and a press of a button whose bound key is in it and down (or pressed this frame) is dropped, since that key types instead; a controller's press, which no key makes, always counts. Constants and sets as in Interfaces; `Pad.new` keeps `gp = pc.gamepad`, `input = pc.input`, `seen = {}`. The key codes (`CODES`) and the guard are the algorithm, so here they are:

```lua
-- The codes (pollEvent's key, isKeyDown's) a bindable key reports, plain
-- and with Shift (API-Input "Key codes").
local CODES = {
    Up = { 0xB5, 0xD6 }, Down = { 0xB6, 0xD7 }, Left = { 0xB4 }, Right = { 0xB7 },
    Enter = { 0x0A, 0xD1 }, Esc = { 0xB1 }, Bksp = { 0x08 }, Del = { 0xD4, 0xD5 },
    Space = { 0x20 }, Ctrl = { 0xA5 },
}
for c = 65, 90 do CODES[string.char(c)] = { c + 32, c } end

-- Whether key `name` is down, or was pressed this frame (a tap shorter than
-- a frame is never down when it is read).
function Pad:down(name)
    for _, c in ipairs(CODES[name] or {}) do
        if self.seen[c] or self.input.isKeyDown(c) then return true end
    end
    return false
end

-- mask less the buttons one of whose keys is in `typing` and down.
function Pad:guard(mask, typing)
    if mask == 0 or not typing then return mask end
    local gp = self.gp
    for _, b in ipairs(Pad.BUTTONS) do
        if mask & b ~= 0 then
            for slot = 0, 1 do
                local name = gp.getLabel(b, slot)
                if name and typing[name] and self:down(name) then
                    mask = mask & ~b
                    break
                end
            end
        end
    end
    return mask
end
```

The rest is one-liners: `frame` resets `seen`; `saw` sets `seen[ev.key] = true` when `ev.key`; `nav/pressed/repeated` return `self:guard(gp.getNavPressed() / getButtonsPressed() / getButtonsRepeated(), typing)`; `any` is `(getNavPressed() | getButtonsRepeated()) ~= 0`; `shift` is `input.getButtons() & input.BTN_SHIFT ~= 0`; `bound(name)` is whether any button's slot 0 or 1 label equals `name`. `label(b, typing, nav)`: when `nav` and `b` is A (or B), return `"Enter"` (or `"Esc"`) if `not self:bound` that key; otherwise the first of slot 0, slot 1 whose name is not in `typing`; else `nil`. `Pad.hint` joins `it[1] .. " " .. it[2]` for each item whose `it[1]` is set.

"""A controller and rebound keys in the simulator (picocalc.gamepad,
firmware 0.7.0): every screen is reached and left with the pad alone, and a
letter bound to a pad button still types."""
import json
import re
import time

from fake_api import last_user_text
from test_chat import mark, no_lua_errors, start_app, type_text, wait
from test_lists_settings import SIM_NOW, seed_chats


def tap(sim, button):
    """A controller's button held 100 ms: no key event, only the pad."""
    sim.pad(button, 100)
    time.sleep(0.3)


def screens_since(sim, m):
    return [l["text"] for l in sim.get_log_lines() if l["seq"] >= m and re.search(r"\[app\] screen ", l["text"])]


def test_controller_alone(llmchat):
    sim, api, data = llmchat()
    seed_chats(data, SIM_NOW)
    wait(sim, r"\[app\] screen chat", start_app(sim))
    time.sleep(0.5)
    # Start Recent chats, B back; A the picker, B back; B Settings, B back.
    for button, screen in (("start", "lists"), ("b", "chat"), ("a", "picker"), ("b", "chat"),
                           ("b", "settings"), ("b", "chat"), ("start", "lists")):
        m = mark(sim)
        tap(sim, button)
        wait(sim, rf"\[app\] screen {screen}$", m)
    tap(sim, "down")
    m = mark(sim)
    tap(sim, "x")  # "Delete this chat?", answered with A
    time.sleep(0.5)
    tap(sim, "a")
    time.sleep(0.5)
    rows = json.loads((data / "chats" / "index.json").read_text())
    assert [r["id"] for r in rows] == ["c1"]
    assert screens_since(sim, m) == [], "the A that answered went on to the list"
    no_lua_errors(sim)


def test_bound_letters_type(llmchat):
    """The browser demo's binding (A is Z, B is X) and Start on S: in the
    compose box and the picker's filter they type; F4 still opens the picker."""
    sim, api, data = llmchat(rebind={"a": ["Z", "F4"], "b": ["X", "F5"], "start": ["F1", "S"]})
    wait(sim, r"\[app\] screen chat", start_app(sim))
    time.sleep(0.5)
    m = mark(sim)
    type_text(sim, "zaxs")
    sim.keypress("\n")
    wait(sim, r"\[chat\] done \d+ chars", m)
    assert screens_since(sim, m) == []
    assert last_user_text([r for r in api.requests if r["stream"]][-1]["body"]) == "zaxs"
    m = mark(sim)
    sim.keypress("f4")
    wait(sim, r"\[app\] screen picker", m)
    time.sleep(0.3)
    m = mark(sim)
    type_text(sim, "s")
    time.sleep(0.5)
    assert screens_since(sim, m) == [], "s filtered"
    sim.keypress("esc")  # clears the filter
    time.sleep(0.3)
    sim.keypress("esc")
    wait(sim, r"\[app\] screen chat", m)
    no_lua_errors(sim)
