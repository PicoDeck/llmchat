# LLM Chat 2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build LLM Chat 2.0 for PicoDeck in its own repo. It chats with Claude and OpenAI with streamed replies, keeps recent chats, and saves the model's Lua programs, which it runs in a sandbox inside the app. Then ship it through the App Store and remove the old app from `picodeck`.

**Architecture:**
- A Lua app in the PicoSurf mould: `main.lua` requires `src.app`, which runs one main loop over four screens.
- Pure modules do the work, each host-tested with a fake `picocalc`: SSE parsing, the two providers, markdown, layout, the store, program extraction and the sandbox.
- Network callbacks only record bytes; parsing happens in the loop.
- Programs run under `xpcall` in a fresh environment whose `picocalc` is an audited allowlist.

**Tech Stack:**
- Lua 5.4 on the PicoDeck firmware: 32-bit integers and floats; no `io`, `os` or `debug`.
- Host tests under `lua5.4` and `build/lua32`.
- pytest with PicoDeck's simulator harness for e2e tests.
- Python 3 for the fixture recorder.
- GitHub Actions; the App Store (indexes repos tagged `picodeck-app`).

**Spec:** `docs/superpowers/specs/2026-10-25-llmchat-design.md`. Read it with this plan; section numbers below (§) refer to it. The mockups are in `docs/mockups/`.

## Global Constraints

**The app and its manifest**
- App id `net.picodeck.llmchat`, directory `llmchat`, version `2.0.0`, category `network`, requirements `["http"]`.
- Data folder `/data/net.picodeck.llmchat/`. Never store app data in `picocalc.config` (4 keys max); only read it, once, for the old-key import (§8.4).

**Claude**
- `anthropic-version: 2026-10-21`.
- Never send `temperature`, `top_p`, `top_k` or `thinking`.
- `max_tokens` 32000; `output_config.effort` from the Thinking setting.
- `"fallbacks": "default"` plus `anthropic-beta: server-side-fallback-2026-07-01`, only for `claude-opus-5-5`, `claude-sonnet-5-5` and `claude-fable-5-1`.

**OpenAI**
- `POST /v1/responses` with `store: false`, `max_output_tokens: 32000` and `stream_options: {include_obfuscation: false}`.
- Never send `max_tokens`, `temperature` or `top_p`.

**Defaults** (copy exactly)
- Provider `claude`.
- Models: Claude `claude-opus-5-5`, OpenAI `gpt-6-luna`.
- Thinking `low`; font `sans`.
- Instructions: `Keep answers short: I'm reading on a 320 px screen.`

**Code and drawing rules**
- Tests pass under both `lua5.4` and `build/lua32`.
- Code must not depend on how `picocalc.json.encode` encodes an empty table: never pass one.
- HTTP callbacks only append data and set flags (firmware runs them between any two Lua statements).
- UI chrome draws in `FONT_6X8`. After drawing in any other font, set `FONT_6X8` back.
- Colours:

  | Use | Colour |
  |---|---|
  | your messages | `rgb(30,58,104)` |
  | Claude bar | `rgb(217,119,87)` |
  | OpenAI bar | `rgb(16,163,127)` |
  | selected row | `rgb(40,70,130)` |
  | code text | `rgb(150,220,150)` |
  | error notes | `rgb(255,110,110)` |
  | dim text | `rgb(130,130,130)` |
- No key binding uses Tab, anywhere.

**Keys and money**
- API keys live only in `~/.config/llmchat/keys.txt` (mode 600) on the laptop and in `keys.txt` on the device. Never commit, log or print a key.
- Real-API spend stays under about $2 in total. Log every real request in `docs/research/api-spend.md`.

**Owner go-ahead and the device**
- Ask the owner before each outward-facing step: creating the GitHub repo, pushing, tagging, changing the store's KV claims, and pushing a `picodeck` branch.
- Before driving the PicoCalc, check that it's idle (status or a screenshot) and ask the owner. A key sent within about 8 s of launching an app is dropped.

**Commits**
- Conventional style: `feat(sse): ...`, `test: ...`, `docs: ...`.

## Review Focus

The spec implies these, but no task would otherwise test them:
1. **A chat, index, prefs or programs file that is corrupt or hand-edited.** The app starts with defaults for that file, renames it to `<file>.bad`, and keeps going. *Test in Task 8.*
2. **A save fails because the card is full or the write fails.** The old file stays intact, the chat shows the error note "Couldn't save: <err>", and the app keeps running. *Test in Task 8.*
3. **Enter pressed twice quickly, or a message of only spaces or newlines.** Exactly one request, or none for blank text. *Test in Task 10.*
4. **Model output with a word or URL wider than the screen, tabs in code, or an unclosed code fence at the end of a reply.** The word breaks inside, tabs become 4 spaces, and the unclosed fence renders as a code panel. *Test in Task 9.*
5. **A program that allocates until memory runs out.** The error screen shows "not enough memory", and the chat draws and sends normally afterwards. *Test in Task 15 (e2e).*
